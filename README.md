# Oh My Prop

> 프랍 트레이딩 서비스로 전환 중입니다. 방향과 순서는 [전환 전략](docs/strategy/README.md), 새 화면 명세는 [트레이더 제품 명세](docs/PROP-PRODUCT-SPEC.md)를 보세요. 아래는 현재(0.2) 구현된 학습 도구의 설명이며, 전환 후 아카데미로 유지됩니다.

프랍 트레이딩의 손실 한도와 거래 기록을 연습하는 한국어 학습용 시뮬레이터. 가상의 고정 기준 규칙과 사용자가 입력한 수치만 사용합니다. 실제 업체의 판정, 거래 조언, 실시간 위험 관리 도구가 아닙니다.

## 공개 화면 (로그인 불필요)

| 경로 | 내용 |
| --- | --- |
| `/` (`index.html`) | 서비스 소개, 시뮬레이션 고지, 현재 무료 시즌 요약, 상품 비교 카드. 유료 평가는 "준비 중 — 유료 평가는 법률 검토 후 제공"만 표시하고 가격·보상 문구는 넣지 않습니다. |
| `/academy/`, `/academy/journal.html` | 기존 학습 도구(계산기·리셋 비교, 가상 거래 연습장). `/journal.html`은 새 위치로 넘겨 주는 안내 페이지입니다. |
| `/leaderboard.html` | 무료 시즌 순위표. 익명 번호, 수익률(베이시스 포인트를 정수 연산으로 % 변환), 상태 배지(기호+글자). |
| `/rules.html?program=<코드>&version=<n>` | 규칙 명세에서 `describeRule`로 생성한 규칙 전문과 버전 해시. 인자가 없으면 상품 목록. |
| `/legal/terms.html`, `/legal/privacy.html` | G0용 이용약관·개인정보 처리방침 **초안**(법률 검토 전, [확정 필요] 항목 포함). |

- 공개 읽기 API(`/api/v2/programs`, `.../versions/{v}`, `.../leaderboard`)만 씁니다. 서버에 연결할 수 없으면(정적 파일로 열었을 때 등) 각 영역에 안내 문구를 표시합니다.
- 공용 머리말·꼬리말은 `src/site/nav.js`가 `#site-header`/`#site-footer` 자리에 그립니다. 스타일은 `src/site/site.css`(다크 테마), `src/site/nav.css`(머리말·꼬리말 전용).
- CSP(`default-src 'self'`)에 맞춰 인라인 스크립트·스타일 없이 모듈 파일과 `textContent`만 씁니다.
- 금지 표현("보장", "원금", "투자 자문" 등)은 `src/site/banned-phrases.js`에 있고, `test/banned-phrases.test.mjs`가 모든 HTML과 `src/**/*.js`를 검사합니다. 예외는 법률 문서의 부정문만 파일+문장 단위로 `ALLOWLIST`에 적습니다.
- `test/site-links.test.mjs`는 모든 HTML의 로컬 href/src 대상 파일이 있는지와 CSP 준수 여부를 검사합니다.

## 트레이더 대시보드 (시뮬레이션)

`/trader.html`은 시뮬레이션 거래 계정 화면입니다. 백엔드(`oh-my-prop/backend`)와 같은 출처에서만 동작합니다.

- 상품별 규칙을 명세에서 생성한 문장으로 보여 주고, 규칙 버전(해시)을 확인해야 계정을 열 수 있습니다.
- 손실 한도 카드: 서버 판정과 같은 한도선·잔여 금액, 남은 비율에 따른 경고 단계(50·25·10%), 가장 가까운 한도, 도달 시 결과(계정 종료 또는 당일 정지)를 보여 줍니다.
- 목표 카드: 수익 목표·거래일·수익일 진행률과 일관성 비율(맞추려면 필요한 총수익)을 보여 줍니다.
- 주문: 시장가·지정가·스톱, 손절·익절. 손절가를 넣으면 "손절가에서 체결되면 얼마를 잃고 일일 한도가 얼마 남는지"를 수수료·슬리피지 포함으로 미리 계산합니다. 가격이 손절가를 건너뛰면 손실이 더 클 수 있다고 함께 알립니다.
- 포지션·미체결 주문·판정·활동 기록은 SSE로 실시간 갱신됩니다. 연결이 끊기면 화면에 표시하고 자동으로 다시 연결해 놓친 이벤트부터 받습니다.
- 응답을 받지 못한 주문은 같은 주문 키로 다시 보내므로 두 번 체결되지 않습니다.
- 거래 복기: 포지션을 줄이거나 닫은 체결을 거래로 세어 누적 확정 손익, 수수료, 승패·승률(본전 제외), 최대 잔고 하락액, 가장 큰 이익·손실, 처음 규칙 위반을 보여 줍니다. 계정의 엔진 이벤트에서 다시 계산하며 따로 저장하지 않습니다.

### 유료 평가 구매

`/trader.html`의 **구매·주문 내역** 화면입니다. 상품 목록의 유료 카드에서 **구매 절차 보기**로 들어갑니다.

- 규칙 전문과 규칙 버전 해시, 청약 철회 조건을 확인해야 주문서를 만들 수 있습니다. 결제 금액은 주문서를 만들 때 서버가 확정합니다.
- **결제 금액은 원화, 계정 잔고는 가상 USD**로 서로 다르게 표시합니다.
- 결제 완료는 서버가 같은 트랜잭션에서 연 계정(`accountId`)이 있을 때만 표시합니다. 응답을 받지 못했거나 결과가 확정되지 않았으면 **"결제가 취소됐는지 확인 중"**, 거절이 확인됐으면 **"취소됨"**으로 구분해 보여 주고, 확인 중에는 주문 상태를 계속 다시 읽습니다.
- 주문 생성의 `Idempotency-Key`는 상품마다 한 번 만들어 세션 저장소에 두고 재전송·새로고침에도 같은 키를 보냅니다. 주문이 중복으로 생기지 않습니다.
- 거래를 시작하기 전까지는 **청약 철회**할 수 있습니다. 결제가 취소되고 계정이 닫힌다는 것을 한 번 더 확인받습니다.
- **실제 결제 수단은 아직 연결되지 않았습니다.** 개발 서버가 `MONEY_DEV_TOOLS`로 모의 결제를 제공할 때만 "개발 도구" 표시와 함께 모의 결제 버튼을 두고, 그렇지 않으면 "결제 수단 연결 전"이라고 표시합니다.
- 서버의 유료 평가 기능이 꺼져 있으면 구매 영역은 "준비 중 — 유료 평가는 법률 검토 후 제공"만 보여 줍니다(홈과 같은 문구).

### 본인확인 (결제 앞단계)

유료 평가는 **만 19세 이상 본인확인을 마친 계정만** 결제할 수 있습니다(서버 규칙: `backend/docs/prop/04-money.md` §6). 구매 화면에서 **1단계 · 본인확인**으로 들어갑니다.

- 확인을 마친 계정은 이 단계를 건너뜁니다. 결제가 `403 identity_required`로 막히면 "결제는 진행되지 않았다"는 안내와 함께 **본인확인으로 가는 버튼**을 바로 띄웁니다.
- 실패는 사유별로 다르게 보여 줍니다: 만 19세 미만, 이미 다른 계정에서 쓴 정보(어느 계정인지는 알려 주지 않습니다), 이미 확인된 계정(그대로 결제로 이어집니다), 요청 만료, 입력 형식 오류.
- 저장되는 것은 **연결정보(CI)의 해시뿐**이며 이름·생년월일 원문은 남지 않는다는 사실을 화면에서 밝힙니다.
- **실제 본인확인 공급자는 아직 연결되지 않았습니다.** 서버가 주는 `redirectUrl`이 개발 경로이면 "개발 도구" 칸에서 값을 직접 받고 *검증하지 않는다*고 표시합니다. 실제 공급자가 붙으면 같은 자리가 공급자 이동 버튼이 됩니다.
- 서버에 본인확인 경로가 없으면(`GET /api/v2/identity`가 404) 이 영역은 조용히 사라지고 구매 흐름은 그대로 동작합니다.

```sh
cd ../backend
# 구매·본인확인 화면을 끝까지 시험할 때
FEATURE_PAID_PROGRAMS=1 FEATURE_IDENTITY_REQUIRED=1 MONEY_DEV_TOOLS=1 npm run dev:sim -- --port 8798
```

로컬에서 가상 시세와 함께 실행하려면:

```sh
cd ../backend
npm run dev:sim     # http://127.0.0.1:8787/trader.html, 데모 로그인은 scripts/dev-sim.mjs 참고
```

`dev:sim`의 시세는 시드 고정 랜덤워크로 만든 **가상 값이며 실제 시세가 아닙니다.**

## 운영 콘솔 (`/admin.html`)

역할(`admin`/`reviewer`)과 2단계 인증이 있어야 열립니다. 개요·계정·이의 제기·**결제·원장**·부정거래 대기열·감사 기록 탭으로 되어 있고, 계정 열람은 모두 감사 기록에 남습니다.

**결제·원장** 탭(`GET /api/v2/admin/money`)은 조회 전용입니다.

- 주문 목록(상태별 거르기), 원장 잔액, 아웃박스 대기/데드레터, 지급 준비금과 신규 펀딩 승급 중단 여부를 한 화면에서 봅니다.
- **미정산 저널(합이 0이 아닌 분개)과 데드레터는 0이 아니면 경고 카드**로 올라옵니다. `paid`인데 계정이 없는 주문도 따로 셉니다.
- 금액은 전부 **원화**이며 `KRW` 꼬리표로 거래 계정의 가상 USD와 구분합니다.
- 환불·취소 버튼은 두지 않습니다. 서버에 그 경로가 없고, 결제를 되돌리는 길은 사용자의 청약 철회뿐입니다.

## 실행

```sh
cd frontend # 이미 저장소 안이라면 생략
python3 -m http.server 8000
```

브라우저에서 <http://localhost:8000>을 엽니다(홈). 학습 도구는 <http://localhost:8000/academy/>에 있습니다. 별도의 의존성 설치가 필요하지 않습니다. 계산기 입력은 저장되지 않지만, 가상 거래 연습장 기록은 해당 브라우저의 로컬 저장소에 저장됩니다. 선택 기능인 계정 동기화는 같은 출처에서 백엔드가 함께 서빙될 때만 동작하며, 정적 서버로만 열면 동기화 패널이 사용 불가로 표시되고 나머지 기능은 그대로 동작합니다.

계정 동기화까지 함께 쓰려면 형제 저장소 `oh-my-prop/backend`를 받아 함께 실행합니다. 백엔드가 API와 이 화면을 같은 출처로 제공합니다.

```sh
cd ../backend
npm start   # http://127.0.0.1:8787
```

## 학습 모델

- 일일 한도선 = 일일 시작 에쿼티 − 초기 잔고 × 일일 손실 한도(%).
- 최대 한도선 = 초기 잔고 − 초기 잔고 × 최대 손실 한도(%).
- 각 잔여 금액 = 현재 에쿼티 − 해당 한도선. 두 잔여 금액 중 작은 쪽이 이 가상 모델의 더 가까운 한도입니다.
- 소수 센트가 생긴 한도선은 보수적으로 올림합니다. 한도선에 도달하거나 그 아래인 경우 위반 가능성으로 표시합니다.

에쿼티에는 평가손익이 반영될 수 있습니다. 수수료·스왑 등 포함 여부는 실제 계좌 자료에 따라 다릅니다. 이 모델은 고정된 최대 손실 기준과 직접 입력한 일일 시작 에쿼티를 가정합니다. 자동 일일 리셋, 추적형 손실, 업체별 규칙과 실시간 시세는 지원하지 않습니다. 실제 사용 전에는 해당 업체의 최신 공식 규정과 계좌 상태를 직접 확인해야 합니다.

### 리셋 전후 비교

[FTMO CFD 2-Step 공개 규칙](https://ftmo.com/en/trading-objectives/)을 참고한 별도의 교육용 시나리오입니다. 초기 가상 자본의 5%를 리셋 시점의 **잔고**에서 빼 일일 한도선을 구하고, 최대 한도선은 초기 자본의 90%로 고정합니다. 전후 리셋 잔고는 직접 입력하며 비교용 에쿼티는 동일하게 유지합니다. 기본 예시에서 한도선이 $95,000에서 $97,000으로 올라가면 에쿼티 $96,000은 그대로여도 새 한도 아래가 됩니다.

리셋 시각과 계좌 이력은 계산하지 않고 입력된 두 스냅샷만 비교합니다. 소수 센트 한도선은 위쪽 센트로 올립니다. 한도와 정확히 같은 경우와 아래인 경우를 구분하지만, 업체의 공식 위반 판정은 아닙니다. 스왑·수수료의 개별 계산, 시점 사이에 발생한 손실, 다른 평가 조건은 포함하지 않습니다.

### 가상 거래 연습장

아카데미 화면의 링크 또는 `/academy/journal.html`에서(이전 주소 `/journal.html`은 새 위치로 안내) 가상 세션의 초기 잔고와 손실 허용률을 정하고, 청산한 가상 거래의 순손익을 차례로 입력합니다. 한도선 도달 이력은 이후 손익이 회복되더라도 유지됩니다. 거래를 삭제하면 남은 거래를 처음부터 다시 계산하므로 이력도 바뀔 수 있습니다.

세션 설정은 입력 중인 초안과 적용된 값을 구분합니다. **설정 적용**을 눌러야 검증·전체 재계산·저장이 일어나고, 거래가 있으면 모든 과거 잔고와 도달 이력을 다시 계산한다는 확인을 받습니다. **변경 취소**는 마지막 적용값을 복원합니다. 적용하지 않은 변경이 있는 동안에는 거래 추가·삭제, 전체 삭제, 백업 가져오기, 서버 동기화를 막고 적용 또는 취소를 안내합니다. 전체 삭제는 삭제할 거래 수와 되돌릴 수 없다는 설명을 확인한 뒤 실행하며 설정은 유지합니다.

저장 상태는 **저장됨**, **이 화면에만 있음(미저장)**, **기존 데이터 읽기 불가** 세 가지로 항상 표시합니다. 저장에 실패하면 화면의 세션을 유지한 채 **저장 다시 시도** 버튼과 백업을 제공하고, 읽을 수 없는 원본은 재시도·가져오기·불러오기 어느 경로로도 덮어쓰지 않습니다.

가상의 단일 세션만 지원하며 미실현 손익, 시세, 실제 주문, 일일 리셋 및 업체별 규칙은 반영하지 않습니다. 수수료 등은 직접 순손익에 포함해야 합니다. 민감한 실제 계좌 정보는 입력하지 마세요.

연습장의 **JSON 백업 다운로드**로 마지막에 적용한 세션을 파일로 보관하고, **JSON 백업 가져오기**로 복원할 수 있습니다. 가져오기는 파일을 검증하고 확인을 받은 뒤 로컬 저장에 성공해야 기존 설정과 거래를 대체하며, 아직 저장되지 않은 내용도 함께 대체됩니다. 최대 크기는 1 MiB이며, 취소하거나 검증·저장에 실패하면 현재 세션을 유지합니다.

백업 파일은 암호화되지 않으며 세션과 거래 이름이 포함됩니다. 안전하게 보관하고 민감한 정보를 입력하지 마세요.

### 계정 동기화 (선택)

백엔드를 같은 출처에서 함께 서빙하면 연습장의 **계정 동기화** 패널에서 이메일·비밀번호로 가입·로그인하고 세션을 **서버에 저장**하거나 **서버에서 불러오기** 할 수 있습니다. 서버에 저장하면 기록이 서버 데이터베이스에 남으므로 민감한 정보를 입력하지 마세요. 불러오기는 확인을 받고 로컬 저장에 성공한 뒤에만 화면을 교체합니다. 서버 기록이 그사이 바뀌면 충돌을 알리고 서버 기록 보기·서버 내용 사용·내 기록으로 덮어쓰기·취소 중에서 선택할 수 있습니다.
