# 01. 시장과 포지셔닝

기준일: 2026-11-14 · 상위 문서: [전환 전략](README.md)

## 1. 프랍 트레이딩 서비스란

이 문서에서 "프랍 트레이딩 서비스"는 리테일 시장에서 통용되는 **평가형 펀딩 프로그램**을 뜻한다.

1. 트레이더가 평가(챌린지) 상품을 선택한다.
2. 정해진 규칙(수익 목표, 일일·최대 손실 한도, 최소 거래일 등) 안에서 거래한다.
3. 규칙을 지키며 목표를 달성하면 펀딩 단계로 올라가고, 펀딩 단계의 성과 일부를 보상으로 받는다.
4. 규칙을 어기면 해당 계정은 종료된다.

기관형 프랍 데스크(회사 자기자본을 직원 트레이더가 운용)는 이번 전략의 대상이 아니다. 자기자본·인가·인력 요건이 리테일 평가 모델과 전혀 다르기 때문이다.

## 2. 시장 현황 요약 `[재검증]`

| 관찰 | 의미 |
| --- | --- |
| 리테일 프랍 시장은 성장 중이나 소규모 업체 정리(분기당 수 곳 폐업·통합)가 계속된다는 보고가 있다 | 진입 장벽은 낮지만 **신뢰·지급 이력이 생존을 가른다** |
| 평가 단계 통과율과 실제 보상 지급 전환율이 낮다(지급 전환 10% 안팎이라는 업계 추정) | 수익 구조가 평가 수수료에 의존한다. 이를 숨기면 신뢰를 잃는다 |
| 미국 CFTC의 MyForexFunds 제재(2023)와 이후 소송 기각(2025) 이후, 업계는 "평가·펀딩 모두 시뮬레이션 계좌", "지급 산식 공개"로 이동했다 | **시뮬레이션 여부와 지급 산식의 명시적 공개**가 사실상 업계 표준이 됐다 |
| 일관성 규칙(특정 하루의 수익 비중 상한)이 주요 업체에 보편화됐다 | 규칙 엔진은 단순 손실 한도를 넘어 **기간 집계 규칙**을 지원해야 한다 |
| 거래 플랫폼 라이선스(예: 특정 플랫폼 공급사의 프랍 업체 라이선스 회수 사례)가 사업 연속성 위험으로 부각됐다 | 체결·시세 계층을 **교체 가능한 어댑터**로 설계한다 |

국내 상황: 금융당국의 2025년 유사투자자문업 점검에서 실현되지 않은 수익률 제시, 손실보전·이익보장 광고, 금융회사로 오인되는 상호 사용이 주요 위반으로 적발됐고, 2026년에는 신고 없는 종목 추천과 미등록 자동매매 프로그램 판매가 단속됐다. 프랍 평가 상품 자체에 대한 당국의 공식 해석은 검색 범위에서 확인하지 못했다. → [03. 규제·리스크](03-compliance-and-risk.md)에서 게이트로 다룬다.

## 3. 대상 고객

| 세그먼트 | 문제 | 우리가 주는 것 | 우선순위 |
| --- | --- | --- | --- |
| **T1. 해외 프랍을 이미 쓰는 한국어 트레이더** | 영문 규정 해석이 어렵고, 규칙 위반을 사후에야 안다. 업체별 규칙이 제각각이다 | 한국어 규칙 설명, 실시간 한도 잔여 표시, 위반 전 경고 | 1순위(검증 대상) |
| **T2. 프랍에 관심 있는 입문자** | 평가에 돈을 쓰기 전에 자기 실력을 알고 싶다 | 무료 시즌 챌린지, 0.2의 학습 도구(아카데미) | 1순위(유입 경로) |
| **B1. 소규모 프랍 업체·브로커** | 규칙 엔진·트레이더 대시보드·부정거래 탐지를 직접 만들기 어렵다 | 화이트라벨 평가 플랫폼(SaaS) | 2순위(병행 준비) |

0.2의 학습 사용자는 T2로 흡수한다. 학습 기능은 삭제하지 않고 **"아카데미"로 무료 유입 경로**가 된다.

## 4. 포지셔닝

> **"규칙이 투명하고, 위반 전에 알려 주는 한국어 프랍 평가 서비스."**

경쟁의 축을 "더 큰 계좌·더 높은 분배율"에 두지 않는다. 자본이 큰 해외 업체와 그 축에서 경쟁할 수 없고, 분배율 경쟁은 지급 불능 위험을 키운다. 대신 다음 세 가지로 차별화한다.

1. **규칙 투명성**: 모든 규칙을 산식과 예시로 공개한다. 화면의 잔여 금액과 서버 판정이 같은 엔진·같은 센트 연산에서 나온다. 판정마다 근거 이벤트를 보여 준다.
2. **사전 경고**: 한도까지 남은 금액, 일관성 규칙 비중, 최소 거래일 진행도를 실시간으로 보여 주고 임계치에서 알린다. "몰라서 떨어지는" 사례를 줄인다.
3. **지급 신뢰**: 지급 산식·심사 기준·처리 기한을 공개하고, 누적 지급 통계를 정기 공개한다(조작 불가능하도록 원장 기반 집계).

## 5. 우리가 이미 가진 것과 부족한 것

| 자산(0.2) | 전환 후 역할 |
| --- | --- |
| 센트 단위 한도선 계산(`risk.js`, `practice.js`) | 규칙 엔진의 기준 구현과 경계값 테스트 |
| 리셋 전후 비교(`reset-scenario.js`) | 일일 리셋 규칙 설명 화면 |
| 계정·세션·리비전 동기화(backend) | 사용자·인증 기반. 저널 모델은 계정(Trading Account) 모델로 확장 |
| 단일 컨테이너·CI | 스테이징 환경의 출발점 |

| 부족한 것 | 담당 |
| --- | --- |
| 시세 수집과 시뮬레이션 체결 엔진 | `data`, `backend` |
| 기간 집계 규칙(일일 리셋, 추적형 손실, 일관성, 최소 거래일) | `backend` |
| 결제·본인확인·보상 지급·원장 | `backend`(법률 게이트 이후) |
| 부정거래 탐지(다계정, 계정 간 헤지, 복사거래) | `data` |
| 다중 환경·관측성·비밀 관리·백업 | `infra` |

## 6. 하지 않을 것

- **실자본 운용·실계좌 주문 중개**: 투자중개·투자일임 인가 영역이다. 이 전략의 어떤 단계도 고객 자금을 시장에 주문하지 않는다.
- **수익 보장·손실 보전 표현**: 광고·화면·약관 어디에도 쓰지 않는다.
- **종목 추천·시그널 판매**: 유사투자자문 영역이며 평가 서비스의 중립성을 해친다.
- **실제 업체명 템플릿 복제**: 규칙은 자체 정의한다. 타사 규칙은 비교 설명 목적으로만 출처와 함께 인용한다.
