# Oh My Prop — 트레이더 제품 명세 (0.3~0.7)

기준일: 2026-11-14 · 상태: 초안 · 상위 문서: [전환 전략](strategy/README.md)

이 문서는 프랍 트레이딩 서비스 전환 후 `frontend` 저장소가 만들 화면과 사용자 흐름을 정의한다. 서버 계약은 `oh-my-prop/backend`의 `docs/PROP-PLATFORM-DESIGN.md`, 규칙 명세 형식은 `oh-my-prop/data`의 `schemas/program-rules.schema.json`을 따른다.

## 1. 정보 구조

```
/                  홈 — 서비스 소개, 시뮬레이션 고지, 현재 시즌, 상품 비교
/academy/          아카데미 — 0.2 학습 도구 재배치(계산기, 리셋 비교, 연습장, 추적형 손실)
/rules/<program>   규칙 설명 — 규칙 명세에서 생성한 산식·예시
/app/              트레이더 앱(로그인 필요)
  accounts         내 거래 계정 목록(시즌·평가·펀딩)
  accounts/<id>    계정 대시보드 + 주문
  accounts/<id>/history   거래·판정 이력, 복기
  payouts          보상 요청·심사 상태(G2 이후)
  settings         보안(2단계 인증), 본인확인, 알림
/leaderboard       시즌 순위표
/transparency      통과율·지급 통계 공개(1.0)
```

0.2의 `index.html`(계산기·리셋 비교)과 `journal.html`(연습장)은 `/academy/` 아래로 옮기고 기존 로컬 저장 키(`oh-my-prop.practice-journal.v1`)와 백업 형식은 그대로 유지한다. 아카데미는 로그인 없이 계속 동작한다.

## 2. 핵심 흐름

### 2.1 시즌 참가 (0.4)

1. 홈에서 현재 시즌의 규칙 요약과 시뮬레이션 고지를 본다.
2. 가입·로그인 후 **참가**를 누르면 규칙 전문 확인 체크(규칙 버전 표시)를 거쳐 계정이 발급된다.
3. 대시보드로 이동해 첫 주문 전에 "한도까지 남은 금액" 카드 설명을 한 번 본다(닫으면 다시 뜨지 않음).

### 2.2 거래와 경고 (0.4)

- 주문 패널: 종목, 방향, 수량, 주문 유형(시장가·지정가·손절·익절). 제출 전에 **"이 주문이 손절가에 도달하면 일일 한도 잔여가 얼마가 되는가"**를 계산해 보여 준다. 손절이 없으면 "손실 상한 계산 불가"를 표시한다. 방향·시점 추천은 하지 않는다.
- 경고 단계: 일일·최대 한도 잔여가 50%, 25%, 10% 이하가 되면 단계별 배너와(동의한 경우) 알림. 경고 문구는 수치만 담는다.
- 위반: 서버 판정 이벤트를 받으면 계정을 읽기 전용으로 바꾸고, 판정 카드(규칙, 기준값, 관측값, 시각, 근거 이벤트 id)를 띄운다. 이의 제기 버튼을 함께 둔다.

### 2.3 유료 평가 구매 (0.6, G1)

상품 비교 → 규칙 전문·환불 정책 확인 → 결제 → 계정 발급. 결제 완료와 계정 발급은 서버의 같은 트랜잭션 결과로만 표시한다(결제 성공인데 계정이 없는 화면 상태를 만들지 않음). 실패 시 "결제가 취소됐는지 확인 중"과 "취소됨"을 구분한다.

### 2.4 보상 요청 (0.7, G2)

지급 가능 금액, 일관성 규칙 비중(예: "최대 수익일 비중 32% / 상한 40%"), 다음 요청 가능일을 보여 준다. 요청 후 상태를 **접수 → 규칙 재검증 → 검토 → 승인 → 송금 완료 / 거절(사유·근거)**로 표시한다.

## 3. 계정 대시보드 구성

| 영역 | 내용 | 갱신 |
| --- | --- | --- |
| 고지 바 | "시뮬레이션 계정 — 실제 시장에 주문이 전달되지 않습니다", 계정 단계, 규칙 버전 | 고정 |
| 한도 카드 | 일일 한도선·잔여, 최대 한도선·잔여(추적형이면 현재 기준점 표시), 가장 가까운 한도 강조 | 실시간 |
| 목표 카드 | 수익 목표 진행률, 최소 거래일 n/N, 일관성 비중 | 체결·거래일 마감 시 |
| 포지션 | 보유 포지션, 평가손익, 손절·익절 | 실시간 |
| 주문 패널 | 2.2 참조 | — |
| 이력 | 체결, 판정 이벤트, 거래일 마감 스냅샷 | 이벤트 시 |
| 복기 | 0.2 백로그 작업 3의 지표(누적 손익, 승·패·본전, 승률, 최대 잔고 하락) + 최초 경고·위반 지점 | 요청 시 |

실시간 수치는 서버 이벤트(SSE)로 받되, **표시용 계산은 같은 규칙 명세를 해석하는 공용 계산 모듈**로 한다. 서버 판정과 화면 수치가 다르면 화면에 "서버 판정 기준으로 표시 중"을 띄우고 서버 값을 우선한다.

## 4. 공용 계산 모듈

- 0.2의 `risk.js`·`practice.js`의 센트 파싱·올림 규칙을 `src/rules/` 아래 규칙 해석기로 정리한다.
- 입력: 규칙 명세(JSON) + 계정 이벤트 목록. 출력: 한도선·잔여·목표 진행·판정 후보.
- 백엔드는 같은 명세를 독립 구현으로 해석한다(0.2의 계약 중복 구현 원칙 유지). 두 구현은 `data` 저장소의 **공용 예시 파일**(`fixtures/rules/*.json`)로 같은 결과를 내는지 각각 테스트한다.

## 5. 문구와 접근성 규칙

- 금지 표현 목록(전략 03 §4)을 상수로 두고, 화면 문구 테스트에서 검사한다.
- 금액은 가상 USD 표시에 "가상" 접두를 붙이는 화면과 결제(원화) 화면을 시각적으로 구분한다.
- 0.2의 기준 유지: 키보드만으로 주요 흐름 수행, 390px 화면 가로 넘침 없음, 색만으로 상태를 구분하지 않음.

## 6. 0.2 백로그와의 관계

| 0.2 백로그 | 처리 |
| --- | --- |
| 작업 2 학습 안내와 예시 | 아카데미로 이동, 0.4에 포함 |
| 작업 3 거래 결과 복기 | 연습장과 계정 대시보드의 복기 영역에 공통 적용 |
| 작업 4 거래 편집과 취소 | 연습장(아카데미)에만 적용. 거래 계정의 체결 기록은 편집 불가 |
| 작업 5 수동 거래일 리셋 | 서버 규칙 엔진의 자동 일일 리셋으로 대체 |
| P3 추적형 최대 손실 | 0.6 1단계 평가 전 아카데미 화면으로 앞당김 |

## 7. 완료 검증 (0.4 기준)

1. 규칙 명세 예시 파일의 모든 사례에서 화면 계산값이 기대값과 센트 단위로 일치한다.
2. 위반 판정 이벤트 수신 시 계정이 즉시 읽기 전용이 되고 판정 카드가 근거를 보여 준다.
3. SSE 연결이 끊기면 "실시간 갱신 중단" 상태를 표시하고 재연결 후 서버 스냅샷으로 맞춘다.
4. 아카데미의 기존 기능과 테스트 33개가 그대로 통과한다.
