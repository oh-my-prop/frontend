# Oh My Prop — 개발 백로그

기준일: 2026-11-04 · 작업 1과 서버 동기화 연동 완료, 작업 2 이후 미착수. 현재 구현은 [제품 기획서](../PRODUCT-PLAN.md)를 기준으로 한다.

## 작업 1 · P0: 기록 변경과 저장 상태 — 완료

목표: 무엇이 변경됐고 브라우저에 남았는지 사용자가 구별한다. 대상은 `journal.html`, `src/journal.js`와 상태 처리 모듈이다.

요구사항:

- 설정은 입력 중 초안과 적용된 값으로 구분한다. 적용 버튼을 누를 때만 검증·재계산·저장한다. 취소는 마지막 적용값을 복원한다.
- 거래가 있으면 설정 적용 전에 모든 과거 잔고와 경계 도달 결과를 다시 계산한다는 안내와 확인을 제공한다. 취소 시 기록·결과·저장값을 바꾸지 않는다.
- 미적용 설정이 있는 동안 거래 추가·삭제·백업 가져오기는 막고 적용 또는 취소를 안내한다. 내보내기는 마지막 적용 세션만 내보낸다고 표시한다.
- 전체 삭제는 삭제할 거래 수와 되돌릴 수 없다는 설명을 확인한 후 실행한다. 설정은 유지한다. 개별 삭제 확인 대신 변경 취소는 작업 4에서 제공한다.
- 상태를 저장 완료, 현재 화면에만 존재, 기존 데이터 읽기 불가로 구분한다. 읽기 불가일 때 원본을 덮어쓰지 않는 기존 동작을 유지한다.
- 일반 저장 실패 시 현재 화면의 세션은 유지하고 백업을 허용한다. 재시도 버튼은 현재 세션의 저장을 다시 시도한다. 읽기 불가 원본은 재시도로 덮어쓰지 않는다.
- 가져오기는 기존처럼 로컬 저장 성공 후에만 세션을 교체한다. 현재 화면에 미저장 데이터가 있으면 그것도 대체된다는 문구를 포함한다.

완료 검증:

1. 거래 2개가 있는 상태에서 설정 변경 취소와 전체 삭제 취소 후 화면·저장값이 동일하다.
2. 설정을 적용하면 모든 거래를 처음부터 재계산하며 새로고침 후 같은 결과가 나온다.
3. 저장 실패를 재현하면 미저장 경고가 보이고 현재 세션을 백업할 수 있다. 재시도 성공 후 경고가 해제된다.
4. 읽을 수 없는 로컬 원본은 어떤 일반 변경이나 가져오기로도 덮어쓰지 않는다.
5. 백업 복원의 실패·취소 보존 동작을 회귀 확인한다.

## 작업 1-S · 0.2: 계정 동기화 연동 — 완료

목표: 기기·브라우저를 바꿔도 연습 기록을 되찾는다. 서버 설계는 별도 저장소 `oh-my-prop/backend`의 백엔드·인프라 기획서에 있다. 대상은 `journal.html`, `src/sync.js`, `src/journal.js`다.

요구사항:

- 로컬 저장이 1차 저장소다. 서버 저장·불러오기는 사용자가 버튼을 누를 때만 실행한다. 자동 백그라운드 동기화는 넣지 않는다.
- 가입·로그인·로그아웃과 현재 계정 표시를 한 패널에서 제공한다. 비밀번호 재설정은 아직 없다는 점을 화면에 밝힌다.
- 서버에서 불러오기는 현재 기록을 대체하므로 확인을 받고, 로컬 저장에 성공해야 화면을 교체한다. 백업 가져오기와 같은 정책이다.
- 서버 리비전이 어긋나면 자동 병합하지 않고 서버 기록 보기·서버 내용 사용·내 기록으로 덮어쓰기·취소를 제공한다.
- 미적용 설정이 있으면 저장·불러오기를 모두 막는다. 백엔드가 없거나 로그인하지 않았으면 패널만 비활성화하고 나머지 기능은 그대로 쓴다.

완료 검증:

1. 가입 → 거래 입력 → 서버에 저장 → 로컬 저장소 삭제 → 새로고침 → 서버에서 불러오기로 같은 기록이 복원된다.
2. 다른 클라이언트가 먼저 저장해 리비전이 어긋나면 충돌 선택지가 뜨고, 서버 내용 사용과 덮어쓰기가 각각 정의대로 끝난다.
3. 미적용 설정 상태에서 저장·불러오기가 막힌다.
4. 백엔드를 끈 채로 열어도 계산·거래·백업 기능에 오류가 없다.

## 작업 2 · P1: 학습 안내와 예시

선행: 작업 1. 홈에서 개념 설명 → 계산 → 리셋 → 연습장 → 복기로 이어지는 순서와 현재 단계를 표시한다. 잔고는 종료된 손익이 반영된 값, 에쿼티는 열린 포지션 손익 등이 반영될 수 있는 값으로 설명한다. 모드별 가정이 다름을 함께 표시한다.

| 예시 | 입력 | 기대 결과와 학습 질문 |
| --- | --- | --- |
| 한도까지 거리 | 초기·일일 시작 100,000, 현재 98,500, 일일 5%, 최대 10% | 일일선 95,000, 최대선 90,000, 가장 가까운 거리 3,500. 어떤 한도가 가까운가? |
| 리셋의 영향 | 초기 100,000, 이전 잔고 100,000, 새 잔고 102,000, 에쿼티 96,000 | 일일선 95,000 → 97,000, 차액 +1,000 → −1,000. 에쿼티가 같아도 왜 달라지는가? |
| 회복 전의 도달 | 초기 100,000, 고정 5%, 거래 −5,000 후 +6,000 | 마지막 잔고 101,000, 잔여 6,000, 최초 도달 1번째 거래. 마지막 잔고만 보면 무엇을 놓치는가? |

각 예시에 예상 결과·짧은 질문·해설을 제공한다. 자동 채점이나 학습 진도 저장은 이번 범위에서 제외한다. 계산기 예시는 해당 입력만 바꾸고 연습장은 바꾸지 않는다. 연습장 예시는 기록이 비어 있지 않으면 대체 확인을 받고, 취소하면 원본을 유지한다. 예시 적용도 작업 1의 저장 실패 정책을 따른다.

완료 기준: 세 예시의 수치가 계산 결과와 일치하고, 키보드만으로 예시 실행·취소·해설 확인·다음 단계 이동이 가능하다. 빈 연습장에서는 다음에 할 행동을 설명한다.

## 작업 3 · P1: 거래 결과 복기

선행: 작업 1·2. 계산은 화면에서 분리하고 `evaluateSession`의 거래 순서와 센트 결과를 사용한다. 새 통계를 백업에 중복 저장하지 않는다.

| 항목 | 명세 |
| --- | --- |
| 누적 순손익 | 마지막 잔고 − 초기 잔고 |
| 승·패·본전 | 순손익이 각각 양수·음수·0인 거래 수 |
| 승률 | 승 / (승 + 패) × 100, 본전 제외. 분모 0이면 ‘계산할 승패 거래 없음’. 표시만 소수 첫째 자리 반올림 |
| 최대 잔고 하락액 | 초기 잔고를 첫 고점으로 포함. 각 거래까지의 최고 잔고 − 해당 거래 후 잔고 중 최댓값. 금액만 표시 |
| 최초 경계 도달 | 기존 최초 도달 거래로 이동하고 강조. 없으면 ‘없음’ |

최대 잔고 하락액은 종료 거래 시점의 관측값이며 장중·미실현 손실이 아님을 설명한다. 그래프는 이번 필수 범위에 넣지 않고 숫자·거래 목록으로 먼저 제공한다.

검증 예시:

- 거래 없음: 손익·하락액 0, 승패본전 각 0, 승률 계산 없음, 최초 도달 없음.
- 초기 100,000, −5,000/+6,000: 손익 +1,000, 승 1·패 1, 승률 50.0%, 최대 하락액 5,000, 최초 도달 1번.
- 초기 100,000, +2,000/−3,000/0/+1,000: 손익 0, 승 2·패 1·본전 1, 승률 66.7%, 최대 하락액 3,000.
- 삭제·설정 적용·복원 후 모든 지표가 같은 규칙으로 갱신된다. 안전한 정수 범위를 넘는 지표는 잘못 표시하지 않고 계산 불가로 처리한다.

## 작업 4 · P2: 거래 편집과 1회 취소

선행: 다음 릴리스 사용자 검증. 거래 이름·순손익을 원래 순서에서 편집하고 전체 재계산한다. 삭제·전체 삭제·설정 적용·편집·예시 대체·백업 복원 직전의 세션을 메모리에 1개 보관해 최근 변경 1회만 취소한다. 거래 추가도 취소 대상이다. 취소 후에는 다시 실행 기능을 제공하지 않는다. 새로고침하면 취소 이력은 사라진다.

취소는 동일한 검증·저장 정책을 사용하고, 취소된 화면과 저장 상태가 일치해야 한다. 잘못된 편집·취소된 확인·실패한 복원은 취소 스냅샷을 교체하지 않는다. 저장소 원본 읽기 불가 상태에서도 원본 보호를 유지한다.

## 작업 5 · P2: 수동 거래일 리셋 설계

선행: 작업 1~3과 사용자 검증. 이 단계는 설계 게이트를 통과한 뒤 구현한다.

- 가상의 규칙 하나만 선택한다. 제안: 일일 한도선 = 해당 거래일 시작 잔고 − 초기 잔고 × 일일 손실률, 전체 한도선은 초기 잔고 기준 고정.
- 종료 거래만 다루며 거래일 시작 잔고는 전 거래일 마지막 잔고에서 유도한다. 첫날은 초기 잔고다. 외부 입출금과 미실현 손익은 제외한다.
- 사용자가 ‘다음 거래일 시작’을 명시적으로 실행한다. 날짜는 학습용 순서이고 자동 시간대·서머타임 처리를 하지 않는다.
- 일일 도달 이력은 거래일별로, 전체 경계 도달 이력은 세션별로 보존한다. 경계 등호 포함 여부를 명시한다.
- 거래일 경계의 삭제·편집과 빈 거래일 처리, 기존 v1 기록의 첫날 이전 방법, 새 백업 버전·구버전 읽기·미지원 버전 거부를 구현 전에 확정한다.

착수 조건: 위 계산 계약과 2일 이상 경계 예시, 데이터 이전 명세가 문서에 있고 검토 가능해야 한다. 실제 업체명 템플릿을 붙이지 않는다.
