# 06. 런칭 계획 — 첫 매출까지

기준일: 2026-11-23 · 상태: 실행 계획 · 상위 문서: [전환 전략](README.md)

이 문서는 "무엇을 더 만들 것인가"가 아니라 **"돈을 받으려면 무엇이 남았는가"**만 다룬다. 릴리스 순서는 [04. 로드맵](04-roadmap-and-metrics.md), 게이트 정의는 [03. 규제·리스크](03-compliance-and-risk.md) 1절을 따른다.

## 한 줄 결론

> **서버는 이미 유료 평가를 팔 수 있다.** 결제 → 원장 분개 → 계정 발급 → 청약 철회까지 실제로 돌려 확인했다(backend PR #8). 남은 차단은 코드가 아니라 **사업자 등록 · 법률 의견서 · PG 가맹** 세 가지이고, 전부 사람이 해야 한다. 코드 쪽에 남은 것은 결제 화면, 본인확인 게이트, 운영 환경이다.

### 실제로 확인한 결제 흐름

`FEATURE_PAID_PROGRAMS=1`로 서버를 띄워 끝까지 실행한 결과다.

| 단계 | 결과 |
| --- | --- |
| 주문 생성 | `201` / 190,000원 / `created` |
| 모의 PG 승인 확인 | `200` `status: paid`, 같은 응답에 `accountId` |
| 발급 계정 | `omp-2step-25k` v1, phase `eval_1` |

## 2. 첫 매출까지의 경로

순서가 있는 이유를 함께 적는다. 앞 단계를 건너뛰면 뒤 단계가 막힌다.

| 단계 | 할 일 | 누가 | 완료 기준 | 막히면 |
| --- | --- | --- | --- | --- |
| **L0** | 사업자 등록, 통신판매업 신고, 사업용 계좌 | 사람 | 약관의 `[사업자 정보 확정 필요]`·`[연락처 확정 필요]`를 채울 수 있다 | PG 가맹 신청 자체가 불가능하다 |
| **L1** | 법률 의견서(G1 질의 항목) | 사람 | 03 §2의 쟁점에 대한 서면 의견 | 유료 판매를 켜면 안 된다 |
| **L2** | PG 가맹 심사 | 사람 | 가맹 승인 + 실연동 키 | 결제 수단이 없다. 업종 사유로 거절될 수 있어 **복수 PG 동시 신청**(03 §3) |
| **L3** | 본인확인 공급자 계약 + 코드 게이트 | 사람 + 코드 | 만 19세 확인, CI 해시로 1인 1계정 | 다계정 부정거래가 열린 채 유료화된다 |
| **L4** | 호스팅·도메인·TLS·백업, stg → prod | 코드(사업자 선택은 사람) | 복구 리허설 통과, 헬스체크 녹색 | 운영 환경이 없으면 판매도 없다 |
| **L5** | 가격·환불 정책 확정, 약관 확정, 플래그 ON | 사람 + 코드 | 구매 → 발급 → 위반 종료 → 재구매 E2E | — |

L1과 L2는 병렬로 간다. L2는 심사에만 수 주가 걸릴 수 있고 `[추정]`, 거절 시 B2B 경로로 전환하는 판단(02 §5)이 필요하다.

## 3. 사람만 할 수 있는 일

코드로 대체할 수 없는 항목이다. 이것들이 런칭의 실제 임계경로다.

| 항목 | 왜 필요한가 | 없으면 막히는 것 |
| --- | --- | --- |
| 사업자 등록증 | 약관·방침의 운영자 정보, PG 가맹 필수 서류 | L0 이후 전부 |
| 통신판매업 신고 | 전자상거래법상 유료 판매 요건 | 유료 결제 |
| 사업용 계좌 + 지급 준비금 계좌 | 원장의 `cash:bank`·`cash:payout_reserve`가 실제 계좌와 대응해야 대사가 성립 | 원장 대사, 보상 지급 |
| 법률 의견서 | G1 게이트 통과 조건(03 §1) | 유료 판매 |
| PG 가맹 | 결제 수단 | 결제 |
| 본인확인 공급자 | 연령·실명·1인 1계정 | 다계정 차단, 지급 심사 |
| 호스팅 사업자 선택 | 국내 리전, 관리형 DB·오브젝트 스토리지·비밀 관리 필요(`infra/docs/INFRA-PLAN.md:27`) | 운영 환경 |
| 도메인 + TLS 인증서 | 쿠키 `Secure`, 같은 출처 전제 | 공개 서비스 |
| 교차 저장소 CI 토큰 | E2E 워크플로가 네 저장소를 체크아웃하지 못한다(`infra` 로그 L-002) | 배포 전 통합 검증 |
| 가격 확정 | `backend/src/money/pricing.js`는 연습용 자리값이라고 파일에 명시돼 있다 | 매출 계산 |
| 베타 사용자 모집 | 04 §1의 0.4 완료 기준(30명 시즌 완주) | 통과율·지급 전환 추정 |

## 4. 코드로 남은 일

우선순위 순. 전부 유료 판매를 켜기 전에 끝나야 한다.

1. **결제 화면**(frontend) — 구매 → 규칙·환불 정책 확인 → 결제 → 발급, 주문 목록과 청약 철회. 서버 계약은 이미 고정돼 있다.
2. **본인확인 게이트**(backend) — 결제 전 연령 확인, CI 해시로 1인 1계정. 공급자는 결제와 같은 패턴(실제 공급자 미정이면 모의 공급자만 허용)으로 추상화한다.
3. **지급 준비금과 승급 중단**(backend) — `미지급 추정액 / 준비금 ≥ 1`이면 신규 펀딩 승급을 자동 중단(04-money §5). 지급 불능이 사업을 끝내는 가장 큰 재무 위험(02 §4)이다.
4. **운영 환경**(infra) — `environments/stg`·`prod`, 배포 태그 묶음, 볼륨 백업, 복구 리허설.
5. **가격·환불 정책을 설정으로** — 코드 상수에서 환경 설정으로 옮기고 변경을 감사 로그에 남긴다.
6. **경고 노출 기록**(backend/data) — "위반 직전 경고를 받았던 비율"이 북극성 보조 지표인데 현재 측정 불가다(경고가 화면에서만 계산된다).

## 5. 다시 추정해야 하는 숫자

02 §4의 단위 경제는 **전부 가설**이고, 지금 그것을 검증할 데이터가 없다. 무료 시즌을 먼저 돌려야 한다.

| 가정 | 현재 근거 | 확정 방법 |
| --- | --- | --- |
| 1단계 통과율 20% | 없음 | 무료 시즌 참가자의 규칙 준수 분포 |
| 지급 전환 30% | 업계 추정 `[재검증]` | 펀딩 단계 운영 후 |
| 고객 획득 비용 ₩40,000 | 없음 | 유입 경로별 실측 |
| 계정당 인프라 비용 ₩8,000 | 없음 | 월 청구서 ÷ 활성 계정 |

가격(₩190,000)은 이 네 숫자가 바뀌면 함께 바뀐다. **통과율이 낮을수록 매출이 느는 구조**라는 점을 04 §3의 북극성 지표가 견제한다.

## 6. 런칭 전 플래그 점검

| 설정 | 유료 출시 시 값 | 지금 기본값 |
| --- | --- | --- |
| `FEATURE_PAID_PROGRAMS` | `1` (G1 의견서 번호를 기록한 뒤) | `0` |
| `FEATURE_PAYOUTS` | `0` (G2 전까지) | `0` |
| `FEATURE_FUNDED_PROMOTION` | `FEATURE_PAYOUTS`와 동일 | 〃 |
| `MONEY_DEV_TOOLS` | **꺼짐** | 운영에서 자동 차단 |
| `MONEY_PROVIDER` | 실제 PG | `mock`만 허용 |
| `ADMIN_REQUIRE_MFA` | `1` | `1` |
| `COOKIE_SECURE` | `1` | production에서 `1` |

`MONEY_PROVIDER`가 `mock` 외 값을 거부하므로, **실연동 코드를 넣기 전에는 실수로도 운영에서 결제를 받을 수 없다.** 이 거부는 유지한다.

## 7. 리스크

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| PG 가맹 거절 | 유료 판매 불가 | 복수 PG 동시 신청, 거절 시 B2B 경로(02 §5)로 전환 판단 |
| 법률 의견서가 "인가 필요" | B2C 중단 | 03 §1에 이미 정해진 경로: B2B를 주 경로로 |
| 통과율 가정이 틀림 | 단위 경제 붕괴 | 무료 시즌 데이터로 가격 재산정 후 출시 |
| 본인확인 없이 출시 | 다계정 부정거래, 미성년 결제 | L3을 L5보다 먼저 끝낸다 |
| 운영 환경 미구성 상태에서 판매 | 장애 시 판정 기록 유실 | L4의 복구 리허설을 출시 조건으로 |

## 8. 다음 행동

- **사람**: L0(사업자 등록)을 가장 먼저 시작한다. 나머지 모든 계약의 선행 조건이다.
- **코드**: 4절 1~3번을 순서대로 끝낸다. 전부 기능 플래그 뒤에 두고, 플래그는 L1·L2가 끝나기 전까지 켜지 않는다.
