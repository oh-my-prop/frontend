# 02. 사업 모델과 상품 설계

기준일: 2026-11-14 · 상위 문서: [전환 전략](README.md)

## 1. 수익원

| 수익원 | 설명 | 켜지는 시점 |
| --- | --- | --- |
| 평가 수수료 | 평가 계정 구매 시 1회 결제. 매출의 대부분 | 법률 게이트 G1 통과 후 |
| 재도전 할인 | 규칙 위반으로 종료된 계정의 재구매 할인 | G1 이후 |
| 화이트라벨 이용료 | B2B 업체의 월 기본료 + 활성 계정당 과금 | 별도 계약 검토 후 |
| 아카데미 | 무료(유입 경로). 유료화하지 않는다 | 즉시 |

**하지 않는 수익원**: 거래 수수료·스프레드 마진(실주문을 하지 않으므로 성립하지 않고, 하게 되면 중개 영역), 시그널 구독, 트레이더 데이터 판매.

## 2. 상품 구성

모든 계정은 **시뮬레이션 계정**이다. 평가·펀딩 단계 모두 실제 시장에 주문이 나가지 않으며, 이 사실을 구매 전·대시보드·약관에 동일한 문구로 명시한다. 금액은 가상 USD로 표시하고 결제는 원화로 한다.

### 2.1 시즌 챌린지 (무료, 0.3부터)

| 항목 | 값 |
| --- | --- |
| 기간 | 14일 시즌, 시즌마다 같은 조건 |
| 가상 잔고 | $25,000 |
| 규칙 | 일일 손실 5%, 최대 손실 10%(고정), 수익 목표 없음 |
| 순위 | 규칙을 지킨 계정만, 수익률 → 최대 잔고 하락률(낮을수록 상위) 순 |
| 보상 | **없음**(현금·경품·포인트 모두 없음). 프로필 배지와 순위 기록만 |

목적은 규칙 엔진·체결 엔진·대시보드를 실제 사용 부하에서 검증하고, 유료 상품의 통과율·위반 분포를 추정할 데이터를 모으는 것이다. 경품을 붙이지 않는 이유는 경품 제공 자체가 별도 규제(경품류 제공 한도, 사행성 판단) 검토 대상이 되기 때문이다.

### 2.2 2단계 평가 (유료, G1 이후)

| 항목 | 1단계 | 2단계 | 펀딩 |
| --- | --- | --- | --- |
| 수익 목표 | 8% | 5% | 없음 |
| 일일 손실 한도 | 5% | 5% | 5% |
| 일일 기준 | 거래일 시작 시점의 max(잔고, 에쿼티) | 동일 | 동일 |
| 최대 손실 한도 | 10% 고정(초기 잔고 기준) | 동일 | 동일 |
| 최소 거래일 | 4일 | 4일 | 지급 주기당 4일 |
| 기간 제한 | 없음(단, 30일 무거래 시 종료) | 동일 | 동일 |
| 일관성 규칙 | 없음 | 없음 | 지급 시 단일 거래일 수익 ≤ 해당 주기 수익의 40% |
| 보상 분배 | — | — | 80% |

### 2.3 1단계 평가 (유료, G1 이후, 2.2 검증 후)

수익 목표 10%, 일일 3%, **종가 기준 추적형 최대 손실 6%**(최고 마감 에쿼티를 따라 올라가다가 초기 잔고에 도달하면 고정). 추적형 규칙은 사용자 오해가 가장 많은 규칙이므로 아카데미에 별도 학습 화면을 먼저 만든다(기존 백로그 P3 "추적형 최대 손실 학습"을 앞당김).

### 2.4 규칙의 버전 관리

- 상품의 규칙은 `program_version` 단위의 데이터(JSON 명세, `oh-my-prop/data`의 `schemas/program-rules.schema.json`)로 정의한다.
- **구매 시점의 규칙 버전이 그 계정의 수명 내내 고정된다.** 규칙 변경은 새 버전으로만 출시한다.
- 화면 설명, 서버 판정, 약관 별표가 같은 규칙 명세에서 생성된다. 문서와 엔진이 어긋나는 일을 구조적으로 막는다.

## 3. 보상 지급 모델

- 지급 재원은 **평가 수수료 매출**이다. 이 사실을 약관과 FAQ에 숨기지 않는다. 펀딩 계정의 손익은 시뮬레이션이며, 보상은 "시뮬레이션 성과에 따른 서비스 보상"이다. 법적 성격(기타소득·사업소득 등)과 원천징수는 G1·G2 의견서로 확정한다.
- 첫 지급 요청은 펀딩 시작 14일 후, 이후 14일 주기. 최소 지급액 $100 상당.
- 지급 심사: 규칙 위반 재검증 → 부정거래 점수 → 본인확인 일치 → 원장 전기 → 송금. 각 단계의 상태를 트레이더에게 그대로 보여 준다.
- 첫 지급 시 해당 계정의 평가 수수료를 함께 환급한다(업계 관행, 매출 인식 시점에 영향 → 회계 처리 확정 필요).
- 계정 규모 확대(스케일링): 연속 2주기 지급 + 주기 수익 ≥ 5% 시 가상 잔고 25% 증액, 트레이더당 합산 상한 $200,000.

## 4. 단위 경제 (가설 모델)

아래 숫자는 **모두 검증 전 가설**이다. 시즌 챌린지 데이터로 통과율·지급 전환율을 다시 추정한 뒤 가격을 확정한다.

가정: $25,000 2단계 평가, 수수료 ₩190,000, 구매 1,000건 기준.

| 항목 | 가정 | 금액(₩) |
| --- | --- | --- |
| 수수료 매출 | 1,000 × 190,000 | 190,000,000 |
| 1단계 통과 | 20% → 200 | — |
| 2단계 통과(펀딩) | 50% → 100 | — |
| 지급 받는 펀딩 계정 | 30% → 30 | — |
| 보상 지급 | 30 × 평균 1,500,000 | −45,000,000 |
| 수수료 환급 | 30 × 190,000 | −5,700,000 |
| 결제 수수료 | 3.5% | −6,650,000 |
| 시세·인프라·본인확인 | 계정당 8,000 | −8,000,000 |
| 고객 획득 비용 | 구매당 40,000 | −40,000,000 |
| **공헌이익** | | **84,650,000 (44.6%)** |

스트레스 시나리오: 지급 전환이 60%, 평균 지급이 ₩3,000,000으로 오르면 보상만 ₩180,000,000이 되어 공헌이익이 음수가 된다. 따라서 다음을 운영 규칙으로 둔다.

1. **지급 준비금**: 직전 90일 수수료 매출의 일정 비율(초기 35%)을 별도 계정에 적립하고, 미지급 보상 추정액이 준비금을 넘으면 신규 펀딩 승급과 스케일링을 멈춘다. 이미 확정된 지급은 멈추지 않는다.
2. **트레이더당 노출 상한**: 스케일링 상한 $200,000, 주기당 지급 상한 설정.
3. **통과율 공개**: 상품별 통과율·지급 전환율을 분기마다 공개한다. 낮은 통과율로 수익을 내는 구조를 감추는 순간 포지셔닝(규칙 투명성)이 무너진다.

## 5. B2B 화이트라벨 경로

같은 규칙 엔진·대시보드·부정거래 탐지를 업체별 테넌트로 분리해 제공한다.

- 업체가 자기 브랜드·자기 상품 규칙(규칙 명세 JSON)·자기 결제를 쓴다. 우리는 고객 자금을 만지지 않는다.
- 과금: 월 기본료 + 활성 계정당 과금. 지급 업무는 업체 책임.
- 선행 조건: 멀티테넌시(`backend`), 테넌트별 데이터 분리와 SLA(`infra`), 규칙 명세 공개 문서.
- 착수 시점: 0.4에서 자체 서비스 대시보드가 안정된 뒤 파일럿 1곳.

B2C의 G1이 통과되지 않으면 B2B가 주 경로가 된다. 두 경로가 같은 엔진을 쓰므로 0.3~0.4의 개발은 어느 쪽 결론에서도 버려지지 않는다.
