# 법률 질의서 초안 — 유료 평가 판매(G1) 전 검토 요청

기준일: 2026-11-23 · 상태: 변호사 전달용 초안 · 상위 문서: [규제·리스크](strategy/03-compliance-and-risk.md), [런칭 계획](strategy/06-launch-plan.md)

> 이 문서는 법률 의견이 아니다. **변호사에게 전달할 사실관계와 질문**을 정리한 것이다. 회신을 받기 전에는 어떤 항목도 결론으로 쓰지 않는다.
>
> 작성 목적: [런칭 계획](strategy/06-launch-plan.md) L1(법률 의견서)은 첫 매출의 임계경로다. 질의 범위가 좁고 사실관계가 구체적일수록 회신이 빠르고 쓸 수 있다.

| 대상 이용자(국내 거주자 한정 여부, 연령) | 외국환거래법·연령 제한 |

## 1. 서비스 사실관계

변호사가 판단에 쓸 수 있도록, **구현된 것만** 적는다. 계획은 7절에 따로 둔다.

### 1.1 한 줄 요약

사용자가 **가상 자금으로 시뮬레이션 거래**를 하고, 사전에 공개된 규칙(손실 한도·수익 목표·최소 거래일)을 지키며 목표를 달성하면 다음 단계로 올라가는 **평가 서비스**다. 평가 참가에 1회 수수료를 받는다.

### 1.2 돈과 자산의 흐름

| 항목 | 사실 |
| --- | --- |
| 고객 자금 운용 | **없음.** 고객 돈을 받아 운용하거나 보관하지 않는다 |
| 실제 주문 전달 | **없음.** 어떤 설정으로도 외부 거래소에 주문을 보내는 코드 경로가 없다 |
| 계정 잔고 | 가상 USD 수치. 출금 불가, 현금 환산 경로 없음 |
| 사용자가 내는 돈 | 평가 수수료 1회, 원화 결제 |
| 사용자가 받을 수 있는 돈 | **현 단계에서 없음.** 보상 지급(G2)은 이 의견서 회신 전까지 켜지 않는다 |
| 시세 | 공개 거래소의 가격을 받아 시뮬레이션 체결에만 쓴다 |

### 1.3 평가 규칙

- 규칙은 JSON 명세로 정의되고 **버전마다 SHA-256 해시로 고정**된다. 구매 시점의 규칙 버전이 그 계정의 수명 내내 적용된다.
- 사용자는 계정을 열기 전에 규칙 전문과 해시를 확인하고 동의한다. 해시가 다르면 계정이 열리지 않는다.
- 판정(위반·통과)은 서버가 입력 기록으로부터 재계산할 수 있고, 판정마다 기준값·관측값·시각·근거 이벤트 id를 사용자에게 보여 준다.
- 사용자는 모든 판정에 이의를 제기할 수 있고, 처음 검토하지 않은 담당자가 다시 본다.

### 1.4 결제와 환불

- 결제는 PG를 통한 1회 결제다(가맹 심사 전).
- 청약 철회: 해당 계정에 **체결이 1건도 없고** 결제 후 7일 이내이면 전액 환불한다. 체결이 있으면 현재 거절한다. ← **질의 대상(3절)**
- 모든 원화 이동은 복식부기 원장에 기록한다(차변·대변 합 0). 결제·환불·PG 수수료가 각각 분개로 남는다.

### 1.5 수집하는 개인정보

| 항목 | 저장 형태 | 목적 |
| --- | --- | --- |
| 이메일 | 평문(로그인 식별자) | 계정 |
| 비밀번호 | scrypt 해시 | 인증 |
| 본인확인 연결정보(CI) | **HMAC 해시만** (원문 미저장) | 만 19세 확인, 1인 1계정 |
| 거래 행태(주문·체결·판정) | 이벤트 로그 | 판정 재현, 부정거래 탐지 |
| 결제 주문 | 금액·상태·PG 결제키 | 결제·환불·대사 |

이름·생년월일·전화번호 **원문은 저장하지 않는다**(본인확인 결과를 해시로만 남긴다).

## 2. 핵심 질의 — 자본시장법

| # | 질문 | 우리 설계의 사실 |
| --- | --- | --- |
| 1-1 | 시뮬레이션 계정의 평가·수수료 수취가 **금융투자상품**의 판매 또는 **투자중개업·투자일임업** 인가 대상에 해당하는가 | 고객 자금 운용 없음, 실주문 없음, 잔고는 출금 불가한 가상 수치 |
| 1-2 | 평가 수수료가 "손익이 연동되는 계약"으로 평가될 여지가 있는가 | 수수료는 결과와 무관한 정액 1회 결제다. 결과에 따른 추가 청구 없음 |
| 1-3 | 보상 지급(G2)을 켜면 1-1의 판단이 달라지는가. 달라진다면 어떤 구조(상금·용역 대가·포상금 등)가 위험이 낮은가 | 지급 재원은 평가 수수료 매출이며, 이를 약관과 FAQ에 공개할 예정 |

## 3. 핵심 질의 — 전자상거래법·약관규제법

| # | 질문 | 우리 설계의 사실 |
| --- | --- | --- |
| 2-1 | 디지털 서비스의 **청약 철회** 범위에서, "거래를 시작하면 환불 불가"가 유효한가. 유효하다면 어떤 고지 방식이 필요한가 | 현재는 체결 0건 + 7일 이내만 환불. 체결이 있으면 거절 |
| 2-2 | **규칙 위반으로 계정이 종료된 경우 환불하지 않는다**는 조항이 유효한가 | 규칙과 판정 근거를 사전·사후에 모두 공개한다 |
| 2-3 | 규칙 전문을 약관 별표로 두고, 규칙 버전이 바뀌면 신규 구매에만 적용하는 방식이 적절한가 | 구매 시점 버전이 계정 수명 내내 고정된다(해시로 증명 가능) |
| 2-4 | 환불 처리 기한과 방법에 법정 요건이 있는가 | 현재 PG 취소로 처리, 처리 상태를 사용자에게 표시 |

## 4. 핵심 질의 — 사행행위·형법상 도박

| # | 질문 | 우리 설계의 사실 |
| --- | --- | --- |
| 3-1 | **유료 참가 + 성과 기반 보상** 구조가 "우연성에 기반한 재물의 득실"로 평가될 위험이 있는가 | 결과는 사용자의 거래 판단과 규칙 준수로 결정된다. 서비스가 결과에 난수를 넣는 요소는 없다 |
| 3-2 | 보상이 없는 **무료 시즌**(순위표와 배지만, 경품 없음)은 사행성 쟁점에서 자유로운가 | 현재 운영 중인 무료 시즌에는 현금·경품·포인트가 전혀 없다 |
| 3-3 | 통과율이 낮을수록 매출이 느는 구조 자체가 문제인가. 통과율 공개가 완화 조치가 되는가 | 분기마다 상품별 통과율을 공개할 계획 |
| 3-4 `[추가]` | 경쟁·순위·등급(라이선스) 요소를 붙이면 **게임산업법상 게임물**에 해당해 등급분류 대상이 되는가 | 현재는 보류한 설계다([게임 레이어](strategy/05-game-layer.md)). 켜기 전에 답이 필요하다 |

## 9. 회신 후 할 일

1. 의견서 문서 번호를 운영 설정에 기록하고 `FEATURE_PAID_PROGRAMS`를 켠다([런칭 계획](strategy/06-launch-plan.md) 6절).
2. `[확정 필요]` 항목을 채워 약관·방침을 확정하고 시행일을 공지한다.
3. 의견이 "불가" 또는 "인가 필요"이면 [사업 모델](strategy/02-business-model.md) 5절의 B2B 경로로 전환한다.
