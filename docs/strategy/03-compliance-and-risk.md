# 03. 규제·리스크·신뢰

기준일: 2026-11-14 · 상위 문서: [전환 전략](README.md)

> 이 문서는 법률 의견이 아니다. 아래 쟁점 목록은 **변호사에게 질의할 항목**을 정리한 것이며, 의견서를 받기 전에는 결론으로 쓰지 않는다.

## 1. 출시 게이트

돈이 오가는 기능은 아래 게이트를 순서대로 통과해야 켠다. 게이트는 기능 플래그로 구현해 코드가 있어도 운영에서 꺼져 있게 한다(`backend` 설계 참조).

| 게이트 | 켜지는 기능 | 통과 조건 |
| --- | --- | --- |
| **G0** | 무료 시즌 챌린지, 아카데미 | 이용약관·개인정보 처리방침 게시, 시뮬레이션 고지 문구 확정 |
| **G1** | 유료 평가 판매 | 2절 쟁점에 대한 국내 법률 의견서, PG 가맹 심사 통과, 환불 정책 확정 |
| **G2** | 보상 지급 | 보상의 법적 성격·과세·원천징수 방식 확정, 본인확인·AML 절차, 지급 준비금 계정 개설 |
| **G3** | 화이트라벨 B2B | 데이터 처리 위탁 계약서 양식, 테넌트 분리 점검, 장애 대응 SLA |

어느 게이트든 의견서가 "불가" 또는 "인가 필요"로 나오면 해당 기능은 켜지 않고 [02. 사업 모델](02-business-model.md) 5절의 B2B 경로를 주 경로로 전환한다.

## 2. 법률 질의 항목

| 쟁점 | 질문 | 우리가 취하는 설계상 완화 조치 |
| --- | --- | --- |
| 자본시장법 — 금융투자상품·투자중개·투자일임 | 시뮬레이션 계정의 평가·보상이 금융투자상품 또는 인가 대상 영업에 해당하는가 | 실주문 없음, 고객 자금 운용 없음, 계정 잔고는 출금 불가한 가상 수치 |
| 유사투자자문 | 규칙 설명·아카데미·대시보드 경고가 투자 판단 조언으로 볼 여지가 있는가 | 종목·방향·시점 추천 금지. 경고는 "사용자가 정한 포지션이 규칙에 미치는 영향"만 계산 |
| 사행행위 규제·형법상 도박 | 유료 참가 + 성과 기반 금전 보상 구조가 우연성에 기반한 재물 득실로 평가될 위험 | 기술·규칙 준수 중심 평가, 결과의 산식 공개, 무료 시즌에는 보상 없음 |
| 유사수신 | 수수료 환급·보상 약속이 원금 보장성 자금 모집으로 오인될 여지 | "원금·수익 보장" 표현 금지, 환급은 조건부임을 명시 |
| 전자상거래법·약관규제법 | 디지털 서비스의 청약철회 범위, 규칙 위반 종료 시 환불 불가 조항의 유효성 | 거래 시작 전 철회 허용, 약관 별표에 규칙 전문 |
| 표시광고법·금융 광고 규제 | 수익률·지급 사례 광고의 허용 범위 | 실현되지 않은 수익률 미표시, 지급 통계는 원장 기반 실적만 |
| 외국환거래법 | 해외 사용자·해외 송금 지급 시 신고 의무 | 0.x 단계는 국내 거주자 한정 |
| 개인정보보호법 | 본인확인·지급 계좌·거래 행태 데이터의 수집 근거와 보존 기간 | 최소 수집, 목적별 보존 기간(`data` 문서), 가명 처리 분석 |
| 세법 | 보상의 소득 구분, 원천징수 의무자, 지급명세서 제출 | 지급 원장에 원천징수 필드를 처음부터 둔다 |

해외 동향 참고 `[재검증]`: 미국에서는 CFTC가 2023년 MyForexFunds를 제재했으나 2025년 법원이 소송을 기각했고, 2026년 하반기에는 평가형 선물 프랍에 대한 감독 범위 의견 수렴이 진행 중이라는 보도가 있다. 공통 요구는 **시뮬레이션 여부, 계좌 보유 주체, 지급 산식의 명확한 공개**다. 우리는 국내 결론과 무관하게 이 공개 수준을 기본값으로 채택한다.

## 3. 운영 리스크

| 리스크 | 시나리오 | 대응 | 담당 |
| --- | --- | --- | --- |
| 지급 불능 | 시장 국면 변화로 펀딩 계정 성과가 동시에 좋아짐 | 지급 준비금과 승급 중단 규칙(02 §4), 트레이더당 노출 상한 | backend·운영 |
| 규칙 판정 오류 | 시세 지연·누락으로 잘못된 위반 판정 | 판정은 원천 이벤트로 재현 가능, 위반 확정 전 시세 품질 검사, 오판 시 계정 복구 절차 | backend·data |
| 시세 품질 | 거래소 피드 단절, 비정상 체결가 | 다중 소스 교차 검증, 이상치 시 체결 보류, 장애 구간 공지 | data |
| 부정거래 | 다계정, 계정 간 반대 포지션 헤지, 복사거래, 지연 차익, 시세 오류 악용 | 행태 지표 기반 위험 점수, 지급 심사 시 수동 검토, 약관에 금지 행위 명시 | data |
| 계정 탈취 | 자격 증명 유출로 펀딩 계정·지급 계좌 변경 | 2단계 인증(펀딩 계정 필수), 지급 계좌 변경 후 7일 지급 보류 | backend |
| 플랫폼 의존 | 외부 거래 플랫폼·시세 공급자의 계약 중단 | 체결·시세 계층 어댑터화, 자체 시뮬레이션 체결 엔진을 기본값으로 | backend·data |
| 결제 차단 | PG가 업종을 이유로 가맹 거절·해지 | 복수 PG 협의, 결제 모듈 추상화, B2B 경로 병행 | backend |
| 평판 | 지급 지연·거절 분쟁의 커뮤니티 확산 | 지급 상태 투명 공개, 거절 사유와 근거 이벤트 제공, 이의 제기 절차 | 운영 |

## 4. 신뢰를 위한 공개 원칙

1. **시뮬레이션 고지**: 모든 계정 화면 상단에 "시뮬레이션 계정 — 실제 시장에 주문이 전달되지 않습니다"를 고정 표시한다.
2. **판정 근거 공개**: 위반·통과 판정마다 기준값, 관측값, 시각, 근거 이벤트 id를 보여 준다.
3. **통계 공개**: 상품별 통과율, 지급 전환율, 평균 지급 처리 기간을 분기마다 공개한다.
4. **규칙 변경 공개**: 새 규칙 버전은 출시 14일 전에 공지하고, 기존 계정에는 소급하지 않는다.
5. **금지 표현 목록**: "보장", "확정 수익", "원금", "무위험", "투자 자문", "증권사" 등은 마케팅·화면·알림 문구 검사에서 차단한다(프런트엔드 문구 테스트).
